### 05.1 Events and map

- **Needs:** 04.2.
- **Builds:** authors and publications create, edit and cancel events (place, time in UTC plus time zone, linked books, invited participants, optional external registration link). Invited participants confirm before they appear. Readers mark Interested or Going. Map of all public events, followed accounts highlighted and filterable; browsing works with location denied. Maps: `react-native-maps` on Android, Leaflet on web (check SDK support, provider terms and keys first). Cancelled events keep a marked page.
- **Tables:** `events`, `event_participants`, `event_works`, `event_intents`.
- **Functions:** `create_event(input) → uuid`, `update_event(id, input)`, `cancel_event(id)`, `confirm_event_participant(event_id, accept)`, `set_event_intent(event_id, intent | null)`. Edits and cancellation emit one in-app event to Interested/Going people. Extend `get_work_connections` with events.
- **Acceptance:** `events_are_explicit`: an unconfirmed participant is hidden; the followed filter uses only real follows; cancellation keeps the page and notifies once; a client cannot create an event for another account. In the book tests, `scan_to_event_respects_relationships`: an event linked to the book shows as "book", another event of its author as "author", of its publication as "publisher"; pending or private links are absent.

### 05.2 Discoveries and location unlock

- **Needs:** 05.1 (variants quoting a manuscript need 03.1 approvals before activation).
- **Builds:** creator screen with several variants (text, images or both) at a chosen place, optional event and work link; map markers showing only title, creator and hint; explicit "Unlock" button on Android while close enough; the reader's collection, readable anywhere afterwards (web shows existing unlocks only). Stop new unlocks (collections kept) or remove completely (content becomes unavailable).
- **Tables:** `discoveries`, `discovery_variants`, `discovery_variant_versions`, `discovery_unlocks`.
- **Functions:** `unlock_discovery(discovery_id, lat, lng, accuracy_m, captured_at) → {variantVersionId}`, `save_variant(...)`, `stop_unlocks(id)`, `remove_discovery(id)`. Private assets through an authenticated check, never public URLs.
- **Rules:** within 100 m, accuracy ≤ 50 m, sample ≤ 30 s old (configurable, tune on devices; not proof against spoofing). Foreground only, no background location permission. The first unlock picks one active variant at random inside a transaction; later calls return the same one. Variant edits affect future unlocks only.
- **Acceptance:** `unlock_is_stable`: two concurrent unlocks give the same variant; a later edit does not replace an existing assignment; the preview exposes no text or image URL; stop keeps collections; full removal returns "unavailable"; outside the radius or with location denied there is no unlock.

### 05.3 Ambient reading theme and device checks

- **Needs:** 02.1 (reuse its device-auth adapter; do not write a second one).
- **Builds:** opt-in automatic reading theme from the Android light sensor (dark below 20 lx, light above 50 lx, 2 s settling; tune on devices), manual override, sensor stopped outside reading screens. Record sensor availability, Android versions and every permission outcome in `docs/testing/devices.md`.
- **Functions:** `readingTheme(lux, current) → "light" | "dark"`.
- **Acceptance:** `sensor_failure_is_recoverable`: no light sensor → manual theme works; values around the boundary do not flicker; biometric cancel does not upload or open; PIN fallback works; web never shows a non-working unlock button.
